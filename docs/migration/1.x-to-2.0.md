# Migrate from tiacore 1.x to 2.0

tiacore 2.0 is a rewrite on Effect 4 and TypeScript 7. It keeps every 1.x
package entry point, export name, CLI flag, exit code and versioned wire
contract. Most projects change a Node.js version and rebuild their cache. This
guide lists everything else that can affect you.

## Upgrade to 2.0

1. Run tiacore on Node.js 22.12 or newer (`^22.12.0 || >=24.0.0`). Node.js 20
   and Node.js 22.0 to 22.11 are no longer supported.
2. Install 2.0:

   ```sh
   npm install -D @lucasacoutinho/tiacore@2
   ```

3. Check the install:

   ```sh
   npx tiacore doctor
   ```

4. Put `--` before the test command in `tiacore verify` when that command has
   options of its own:

   ```sh
   npx tiacore verify --output .tia/verification.json -- node run.mjs --flag
   ```

   Without `--`, the parser rejects `--flag` with `Unrecognized flag`. 1.x
   forwarded it. A command without options, such as `npm test`, needs no change.

5. Run your tests once. The first run records a new baseline and runs the full
   suite. The Vitest plugin prints
   `TIA recording full-suite baseline (no compatible graph found).`
6. If CI caches `.tia/`, let the first 2.0 run save the new cache. 2.0 never
   reads the old entries.
7. Check every coverage threshold glob. A glob that matches no file now fails
   the run with an error such as
   `Coverage threshold <name> matches no files, so it cannot be met`. 1.x let it
   pass.

You do not need to change imports or peer versions.

## Effect stays inside

tiacore is written on Effect, and the package bundles it. You install no Effect
package and write no Effect code. No public type mentions Effect, so there is no
Effect syntax to learn. The public API is plain TypeScript with `Promise`. If
you test with `@effect/vitest`, tiacore needs no extra setup. See
[Testing with `@effect/vitest`](../guides/getting-started.md#testing-with-effectvitest).

## Package changes

| Item             | 1.x                                                         | 2.0                                                          |
| ---------------- | ----------------------------------------------------------- | ------------------------------------------------------------ |
| Node.js          | `^20.0.0 \|\| ^22.0.0 \|\| >=24.0.0`                        | `^22.12.0 \|\| >=24.0.0`                                     |
| Module format    | ESM and CommonJS                                            | ESM only                                                     |
| Entry points     | 17 subpaths                                                 | The same 17 subpaths and export names, plus `./package.json` |
| `main`, `module` | `./dist/index.cjs`, `./dist/index.js`                       | Removed. Use `exports`.                                      |
| CLI binary       | `tiacore` at `dist/entries/cli.js`                          | The same                                                     |
| Peers            | `vitest` >=4.1 <6, `vite` >=6 <9, `@playwright/test` >=1.46 | The same, all optional                                       |
| Dependencies     | included `commander`                                        | `commander` removed, `ws` added                              |

### Use require() from CommonJS

`require()` loads the ESM package on Node.js 22.12 and newer, so a CommonJS
project keeps working:

```js
const { tia } = require('@lucasacoutinho/tiacore/vitest')
```

`require('@lucasacoutinho/tiacore')` still returns an object with `tia` and
`default`.

## CLI changes

Every 1.x command and flag still exists. Exit code 0 means success, and every
failure exits with 1, as in 1.x.

| Change                      | What happens now                                                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tiacore verify`            | A test command with options needs `--` before it. `--output`, `--cwd` and `--artifacts` are unchanged.                                                         |
| `tiacore doctor`            | Runs without `--graph` and checks the install. `--graph <file>` validates a graph as before. New flags: `--perf`, `--json`, `--cache-dir`. `--output` is kept. |
| `tiacore devtools`          | New. Hosts a server for spans and metrics. Flags: `--port`, `--host`, `--interval`.                                                                            |
| `tiacore help <command>`    | Removed. Use `tiacore <command> --help`.                                                                                                                       |
| `-v`                        | Accepted now. It prints `tiacore v<version>`. `--version` and `-V` print the bare version.                                                                     |
| `--completions`, `--wizard` | New global flags from the CLI library: shell completion scripts and a guided prompt.                                                                           |
| `--log-level`               | New global flag that sets the minimum log level.                                                                                                               |
| Help text                   | The text changed. Help is not part of the CLI contract, so do not parse it.                                                                                    |

The JSON that the commands print is the same as in 1.x. The k6, Gradle and
Maestro commands are compared with the 1.x binary in
`test/cli/adapters.test.ts`.

[Observability](../observability.md) documents `doctor` and `devtools` in full.

## Protocol files

The specs, JSON Schemas, conformance vectors and adapter capability contract
moved from the package root (`spec/`, `schemas/`, `conformance/`,
`capabilities/`) to `docs/protocol/`. A tool that reads them from the installed
package must use the new paths, such as
`node_modules/@lucasacoutinho/tiacore/docs/protocol/schemas/`.

## Cache and artifacts

The runtime graph is schema 6 and the store is version 4. In 1.x they were
schema 4 and version 2. Three things changed in the layout. Records are ordered
by UTF-16 code unit. The list of working-tree files is stored as its own object,
so the old limit on dirty files is gone. Each Vitest test file records the files
its module load and hooks touched, so a run that replays some of its tests keeps
that evidence.

- 2.0 ignores a 1.x `.tia/` directory and records a new baseline. 1.x ignores a
  2.0 cache the same way, so a rollback also starts with a full run. You can
  delete `.tia/` to reclaim the space. Nothing in it is portable.
- The first run after the upgrade is a full run. Graph digests change once.
- Artifacts keep their format: attestation v1, manifest v1, and the schema-3
  `graph.json`. 2.0 restores artifacts that 1.x published, and each version
  verifies the other's signatures. A pipeline can run both versions while you
  upgrade.
- Restore skips a candidate whose baseline commit is not an ancestor of `HEAD`.
  1.x committed such a graph and then ran the full suite. 2.0 skips it and
  records a new baseline. A candidate with a file-snapshot baseline needs no
  ancestor.
- A manifest with one invalid entry yields no candidates. 1.x dropped the bad
  entry and read the rest.
- Every artifact request has a 60 second deadline, including its body. A failure
  message never carries a header or token. Listings are limited to 10 MiB.
  Archives are limited to 10,000 entries, 64 MiB inflated, 8 nested archives and
  a 500:1 expansion ratio above 1 MiB.
- Published archives are deterministic. Equal graphs under one clock give the
  same bytes, digest and name.
- Signing keys can be PEM, PEM with literal `\n`, or base64 DER.

## Environment variables

New variables turn on observability. All are off by default.

| Variable               | Purpose                                                      |
| ---------------------- | ------------------------------------------------------------ |
| `TIACORE_DEVTOOLS`     | Send spans and metrics to a `tiacore devtools` server.       |
| `TIACORE_OTLP_URL`     | Send traces, metrics and logs to an OTLP/HTTP collector.     |
| `TIACORE_TRACE_FILE`   | Write finished spans to a JSON file.                         |
| `TIACORE_METRICS_FILE` | Write metrics in Prometheus text format.                     |
| `TIACORE_CRASH_DIR`    | Move crash reports from `.tia/crashes` to another directory. |

Crash reports are always on. A defect writes one and prints its path. The
directory keeps the 20 newest. The values and file formats are in
[Observability](../observability.md).

`TIA_FRESH` changed. It accepts `1`, `true`, `yes` and `on`, in any case, in
every runner and in the Go and Python SDKs. In 1.x only the Vitest plugin
accepted the words. Playwright, the shared engine and the Go SDK accepted only
`1`, and the Python SDK ignored the variable. A value such as `TIA_FRESH=true`
now forces a full run in all of them.

`tiacore verify` clears an inherited `TIA_FRESH` for the selective phase, also
when you pass it in `environment`. The full phase always sets it to `1`.

Every other variable keeps its 1.x name.

## Behavior changes by area

These are the changes a project can notice.

### Selection and graph

- Sorting uses UTF-16 code unit order, not the locale.
- A trailing slash is dropped, so `a` and `a/` are one path.
- `allowedSuites` limits the dependency closure to the allowed suites and
  reports the dependents it left out.
- The runtime planner no longer misses tests in `__tests__` directories.
- Results of test files that no longer exist are neither replayed nor counted.
- A file instrumented again during a run counts from zero. 1.x lost the
  increments.
- A FIFO in the project blocked the baseline read in 1.x. Now a baseline hashes
  directories, FIFOs and sockets as unavailable, and refuses files of 2 GiB or
  more by size.

### Vitest

- With `@effect/vitest`, coverage of a layer's construction and finalizers
  belongs to every test of the file. Editing a module a layer uses selects the
  whole file. The
  [guide](../guides/getting-started.md#testing-with-effectvitest) names the two
  cases where `tiacore verify` reports different evidence.

### Playwright

- A filter list over 24,000 characters falls back to a full run and says why.
- The incomplete-evidence warning keeps its text and adds `TIA detail:` lines
  and `result.notes`.
- The count of cached tests leaves out specs that rerun.
- Imports are read with `es-module-lexer`, not a regular expression. A source
  map under `node_modules` is never attributed.
- Selection is file-level. A run commits `complete: true` and
  `coverageComplete: false`, and it replays nothing.
- Changing the run arguments forces a full record. 1.x did the same without
  documenting it.

### Node, Bun, and workspaces

- A Node aggregate pass with a module failure, crash or timeout reports
  `success: false`, saves no graph and commits nothing.
- The execution child group gets `SIGKILL` at 30 seconds. Discovery and
  execution children die with the run and take their temporary directories.
- `test.skip` and `it.todo` through `require("node:test")` record as skipped.
- A `concurrency` of `NaN` is rejected when the configuration is decoded. 1.x
  dropped work or ran without a bound.
- Bun `describe`, skip and todo cases are still module failures. This is
  deliberate and unchanged.

### Gradle, k6, and Maestro

- Gradle rejects result XML older than the run start.
- k6 ignores type-only imports. A profile that cannot be lexed makes a full run
  before anything executes. A successful run with such a profile writes a
  `complete: false` graph.
- Maestro follows `runFlow` transitively, scans every YAML document, and
  excludes `config.yaml` and `config.yml` at the flows root only.
- Running children stop when an external-suite run fails or is interrupted.

### Verification and certification

- The selection audit uses the planner's own kernel, so verifier and planner
  cannot drift. A failed test in a file without per-test edges now requires the
  whole file.
- A malformed snapshot or plan fails with `invalid TIA verification snapshot`.
- `tiacore certify execute --spec` decodes the spec. A malformed spec fails at
  once.
- `record --graph-options` decodes its invalidators and observations with the
  protocol schemas. Unknown keys are still ignored.

## Python and Go SDKs

Both SDKs now reproduce every protocol vector in
`docs/protocol/conformance/protocol/v1`. They share the TypeScript planner's
reasons, check order and glob subset, so a project that matched on 1.x reason
text may see it change. Fixes include `build` and `dist` paths, packages at the
project root, and the `dependsOn` closure. The Python SDK is version 2.0.0, like
the package. The Go SDK has no version of its own. Install it from an exact
commit, as before.

## Known limits

- **Verify snapshots.** `tiacore verify` compares phase snapshots. The Vitest,
  Node, Bun, Playwright and TypeScript adapter runners write them. k6, Gradle,
  Maestro, and the Python and Go SDKs plan impact graphs but run no tests, so
  they write none. A verification that reaches only them fails with
  `snapshot-invalid`. The 1.x documentation said every runner wrote snapshots.
- **Detached fibers.** With `@effect/vitest`, a fiber started by
  `Effect.forkDetach` that finishes during a later test gets that test's
  coverage. If the first test is replayed, the fiber does not exist, the module
  it touched becomes unknown to the graph, and the next edit to that module runs
  the full suite. `tiacore verify` reports the difference. Finish or interrupt
  fibers before the test body ends.
- **Interrupted external suites.** Interrupting a k6, Gradle or Maestro run from
  code kills the suite process but not its children. Ctrl-C in a terminal
  reaches them.
- **One reporter per process.** Only the first Vitest instance in a process gets
  the tiacore reporter. This is the 1.x behavior.
- **Artifact directory.** The filesystem artifact sink keeps every archive it
  wrote. Prune the directory yourself.

## Roll back

Install the 1.x version again. 1.x ignores the 2.0 cache and records its own
baseline on the first run.
